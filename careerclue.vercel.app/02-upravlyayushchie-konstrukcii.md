## `defer` — механика и порядок исполнения

`defer` откладывает вызов функции/метода до момента выхода из окружающей функции (нормального `return` или паники) — независимо от того, сколько именно `defer`-вызовов встретилось по пути и в каком порядке. Порядок исполнения — LIFO (last-in-first-out, как стек): самый последний по коду `defer` выполняется первым при выходе. Критичный нюанс, который часто путают — **аргументы** отложенного вызова вычисляются немедленно, в момент выполнения самой строки `defer`, а не позже, в момент фактического исполнения (`defer fmt.Println(x)` захватывает значение `x` на момент строки `defer`, даже если `x` изменится до реального выхода из функции; чтобы использовать актуальное на момент выхода значение — нужно оборачивать вызов в замыкание: `defer func() { fmt.Println(x) }()`). `defer` выполняется даже при панике — это и есть основа механизма `recover` (см. файл 07): без `defer` перехватить панику в принципе нельзя, `recover()` имеет смысл только будучи вызванным изнутри отложенной функции. Именованные возвращаемые значения (named return values) доступны и изменяемы внутри `defer`-функции уже после выполнения тела функции, но до фактического возврата управления вызывающей стороне — это открывает идиоматичный способ модифицировать возвращаемое значение по итогам восстановления после паники (типичный паттерн: `func f() (err error) { defer func() { if r := recover(); r != nil { err = fmt.Errorf(...) } }() ... }` — иначе после `recover()` без именованного возврата функция просто продолжит выполнение с зануленным/нулевым результатом, не подавая наружу признак того, что вообще была паника). [30]

Тонкий нюанс, регулярно ловящий кандидатов именно на живом разборе кода: `recover()` перехватывает панику, только если вызван **напрямую внутри той функции, которая была непосредственно зарегистрирована через `defer`** — а не в какой-либо вложенной функции, вызванной из неё, даже если эта вложенная функция тоже анонимная. То есть:
```go
defer func() {
    helper() // recover() внутри helper НЕ поймает панику вызывающей функции
}()

func helper() {
    if r := recover(); r != nil { // не сработает — recover вызван не там, где нужно
        fmt.Println("recovered:", r)
    }
}
```
Правильный паттерн — `recover()` должен стоять непосредственно в теле той функции, что передана в `defer`, без промежуточного вызова:
```go
defer func() {
    if r := recover(); r != nil {
        fmt.Println("recovered:", r)
    }
}()
```
Причина — `recover()` привязан к конкретному фрейму стека той функции, что была зарегистрирована через `defer`; вызов из глубже вложенного фрейма (даже если тот фрейм создан прямо внутри той же самой defer-функции) уже не «видит» паникующий фрейм как непосредственно свой родительский. [72]
