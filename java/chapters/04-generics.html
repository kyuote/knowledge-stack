Глава 04

Дженерики

Параметры типа, wildcards, type erasure — то что позволяет писать типобезопасный код без дублирования. Wildcards — самая частая точка путаницы на собесе.

4.1Параметры типа

Дженерики позволяют писать код, работающий с разными типами, при этом сохраняя типобезопасность на этапе компиляции.

Box.java
// Обобщённый класс
class Box<T> {
    private T value;
    public Box(T value) { this.value = value; }
    public T get() { return value; }
}

Box<String>  strBox = new Box<>("hello");  // diamond operator <>
Box<Integer> intBox = new Box<>(42);

// Обобщённый метод
class Utils {
    public static <T> List<T> repeat(T item, int times) {
        List<T> list = new ArrayList<>();
        for (int i = 0; i < times; i++) list.add(item);
        return list;
    }
}

// Несколько параметров типа
class Pair<A, B> {
    final A first;
    final B second;
    Pair(A first, B second) { this.first = first; this.second = second; }
}

4.2Wildcards: ? extends / ? super

Мнемоника: PECS — Producer Extends, Consumer Super. Если объект производит данные (читаем из него) — ? extends. Если потребляет (пишем в него) — ? super.

Wildcards.java
// ? extends T — можно ЧИТАТЬ как T, нельзя ПИСАТЬ (Producer)
List<? extends Number> nums = List.of(1, 2.5, 3L);
Number n = nums.get(0);  // OK — всё является Number
// nums.add(1);          // ошибка компиляции — не знаем точный тип

// ? super T — можно ПИСАТЬ T и его подтипы, читать только Object (Consumer)
List<? super Integer> sink = new ArrayList<Number>();
sink.add(42);            // OK — Integer подходит
sink.add(100);           // OK
// Integer x = sink.get(0); // ошибка — возвращает Object

// Пример PECS: копирование из src в dst
static <T> void copy(List<? extends T> src,   // читаем
                      List<? super T> dst) {    // пишем
    for (T item : src) dst.add(item);
}

// Неограниченный wildcard — только читаем, не знаем тип
void printAll(List<?> list) {
    for (Object o : list) System.out.println(o);
}

4.3Type erasure

Дженерики в Java реализованы через стирание типов: вся информация о типовых параметрах удаляется компилятором. В runtime List<String> и List<Integer> — одно и то же: List.

Erasure.java
// Последствия type erasure:

// 1. Нельзя создать массив обобщённого типа
// T[] arr = new T[10]; // ошибка компиляции

// 2. instanceof не работает с параметрами типа
List<String> list = new ArrayList<>();
System.out.println(list instanceof List<String>); // true (OK в Java 16+)
// до Java 16:
System.out.println(list instanceof List);  // true — только так

// 3. Перегрузка по обобщённому типу невозможна
// void process(List<String> l) {}
// void process(List<Integer> l) {} // ошибка — одинаковые сигнатуры после erasure

// 4. Unchecked cast при получении из raw type
List raw = new ArrayList();
raw.add("hello");
String s = (String) raw.get(0); // работает, но небезопасно

4.4Bounded type parameters

Bounds.java
// Верхняя граница — T должен быть Comparable
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
max(3, 7);       // 7
max("apple", "banana"); // "banana"

// Несколько ограничений (класс первым, потом интерфейсы)
class Container<T extends Serializable & Comparable<T>> { }

// Рекурсивный дженерик (Comparable pattern)
class SortedList<T extends Comparable<? super T>> {
    // работает с Integer, String и их подтипами
}
