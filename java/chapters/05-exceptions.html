Глава 05

Исключения

Иерархия Throwable, checked vs unchecked, try-with-resources. Знание иерархии и правила «не глотать исключения» — обязательны.

5.1Иерархия Throwable

hierarchy.txt
Throwable
├── Error                    // системные ошибки — не перехватывай
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── AssertionError
└── Exception
    ├── IOException          // checked — компилятор требует обработки
    ├── SQLException         // checked
    ├── ParseException       // checked
    └── RuntimeException     // unchecked — не требует обработки
        ├── NullPointerException
        ├── IllegalArgumentException
        ├── IllegalStateException
        ├── IndexOutOfBoundsException
        ├── ClassCastException
        └── UnsupportedOperationException

5.2Checked vs Unchecked

Checked — наследники Exception (кроме RuntimeException). Компилятор требует либо try-catch, либо объявления в throws. Означает: ситуация предсказуема, вызывающий код должен её обработать.

Unchecked (RuntimeException) — ошибки программирования. Не нужно объявлять. На практике большинство современных библиотек предпочитают unchecked.

CheckedDemo.java
// Checked — должен быть обработан или объявлен
void readFile(String path) throws IOException {  // объявляем
    FileReader fr = new FileReader(path);        // бросает IOException
}

void safe() {
    try {
        readFile("data.txt");
    } catch (IOException e) {
        System.err.println("Ошибка: " + e.getMessage());
    }
}

// Unchecked — объявлять не обязательно
void process(String s) {
    if (s == null) throw new IllegalArgumentException("s must not be null");
    // NullPointerException если s.length() был бы null — тоже unchecked
}

5.3try-catch-finally

TryCatch.java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Поймали: " + e.getMessage()); // "/ by zero"
} catch (RuntimeException e) {
    // более широкий catch — порядок от частного к общему!
} finally {
    // выполняется всегда: и при исключении, и без него
    // используй для освобождения ресурсов (если не try-with-resources)
}

// Multi-catch (Java 7+)
try {
    // ...
} catch (IOException | SQLException e) {
    log(e);  // одна обработка для нескольких типов
}

// Переброс исключения
try {
    riskyMethod();
} catch (Exception e) {
    throw new RuntimeException("Контекст: " + e.getMessage(), e); // цепочка!
}
Никогда не делай пустой catch (Exception e) {} — это «глотание» исключения. Минимум — логируй: log.error("msg", e).

5.4try-with-resources

Автоматически закрывает ресурсы, реализующие AutoCloseable. close() вызывается даже при исключении — аналог defer в Go.

TryWith.java
// Старый способ (до Java 7) — легко забыть закрыть
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("file.txt"));
    System.out.println(br.readLine());
} finally {
    if (br != null) br.close(); // IOException здесь может перекрыть первое!
}

// try-with-resources — ресурс закроется автоматически
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    System.out.println(br.readLine());
}  // br.close() вызовется здесь в любом случае

// Несколько ресурсов — закрываются в обратном порядке
try (Connection conn = ds.getConnection();
     Statement  stmt = conn.createStatement()) {
    stmt.execute("SELECT 1");
}

// Свой AutoCloseable
class Timer implements AutoCloseable {
    long start = System.nanoTime();
    @Override
    public void close() {
        System.out.println("Elapsed: " + (System.nanoTime() - start) + "ns");
    }
}
try (var t = new Timer()) {
    // ... код
}  // выведет время автоматически

5.5Кастомные исключения

Custom.java
// Unchecked (чаще всего нужен именно этот вариант)
public class UserNotFoundException extends RuntimeException {
    private final long userId;

    public UserNotFoundException(long userId) {
        super("User not found: " + userId);
        this.userId = userId;
    }

    // Конструктор с cause — для цепочки исключений
    public UserNotFoundException(long userId, Throwable cause) {
        super("User not found: " + userId, cause);
        this.userId = userId;
    }

    public long getUserId() { return userId; }
}

// Checked (когда вызывающий обязан обработать)
public class InsufficientFundsException extends Exception {
    private final double amount;
    public InsufficientFundsException(double amount) {
        super("Insufficient funds: need " + amount);
        this.amount = amount;
    }
}
