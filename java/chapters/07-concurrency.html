Конкурентность

Thread, synchronized, volatile, Lock, ExecutorService, CompletableFuture — самая сложная тема Java-собеса. Нужно понимать модель памяти и проблемы гонок данных.

7.1Thread и Runnable

Threads.java
// Способ 1: Runnable + Thread
Runnable task = () -> System.out.println("Hello from " + Thread.currentThread().getName());
Thread t = new Thread(task, "worker-1");
t.start();   // запускает поток
t.join();    // ждём завершения (блокирует текущий поток)

// Способ 2: наследование Thread (не рекомендуется)
class MyThread extends Thread {
    @Override public void run() { System.out.println("running"); }
}

// Способ 3: Callable — возвращает результат и может бросить исключение
Callable<Integer> compute = () -> {
    Thread.sleep(100);
    return 42;
};

// Жизненный цикл потока: NEW -> RUNNABLE -> BLOCKED/WAITING/TIMED_WAITING -> TERMINATED
Thread.State state = t.getState();

// Полезные методы
Thread.currentThread().getName();
Thread.sleep(100);          // InterruptedException!
Thread.currentThread().interrupt(); // установить флаг прерывания
Thread.currentThread().isInterrupted();

7.2synchronized и volatile

synchronized — монопольный доступ к блоку кода, обеспечивает взаимное исключение и видимость изменений. volatile — гарантирует только видимость (не атомарность).

Sync.java
class Counter {
    private int count = 0;

    // synchronized метод — лок на this
    public synchronized void increment() { count++; }
    public synchronized int get() { return count; }

    // synchronized блок — лок на произвольный объект (гранулярнее)
    private final Object lock = new Object();
    public void add(int n) {
        synchronized (lock) { count += n; }
    }
}

// volatile — гарантирует чтение из основной памяти (не из кэша потока)
// Без volatile другой поток может не увидеть изменения
class StopFlag {
    private volatile boolean running = true;

    void stop() { running = false; }

    void run() {
        while (running) {  // без volatile может крутиться вечно
            // work...
        }
    }
}

// volatile НЕ делает count++ атомарным! Нужен AtomicInteger
AtomicInteger atomicCount = new AtomicInteger(0);
atomicCount.incrementAndGet(); // атомарный инкремент
atomicCount.compareAndSet(expected, newValue); // CAS
count++ — три операции: read, increment, write. Даже с volatile это не атомарно. Используй AtomicInteger или synchronized.

7.3Lock и ReentrantLock

ReentrantLock гибче synchronized: поддерживает tryLock с таймаутом, fairness, несколько условий. Всегда освобождай в finally.

Locks.java
ReentrantLock lock = new ReentrantLock();

void process() {
    lock.lock();
    try {
        // критическая секция
    } finally {
        lock.unlock(); // ВСЕГДА в finally
    }
}

// tryLock — не блокирует
boolean acquired = lock.tryLock(1, TimeUnit.SECONDS);
if (acquired) {
    try { /* ... */ } finally { lock.unlock(); }
}

// ReadWriteLock — несколько читателей, один писатель
ReadWriteLock rwLock = new ReentrantReadWriteLock();
rwLock.readLock().lock();  // несколько потоков могут держать одновременно
rwLock.writeLock().lock(); // монопольный доступ

// Condition — аналог wait/notify, но гибче
Condition notFull  = lock.newCondition();
Condition notEmpty = lock.newCondition();
notFull.await();   // ждать (освобождает lock)
notEmpty.signal(); // разбудить один поток

7.4ExecutorService и пулы

Вместо ручного создания потоков — пулы через Executors. Потоки переиспользуются, управляется очередью задач.

Executor.java
// Фиксированный пул
ExecutorService pool = Executors.newFixedThreadPool(4);

// Кэширующий пул — создаёт потоки по мере надобности
ExecutorService cached = Executors.newCachedThreadPool();

// Одиночный поток — задачи выполняются последовательно
ExecutorService single = Executors.newSingleThreadExecutor();

// ScheduledExecutorService — отложенные/периодические задачи
ScheduledExecutorService sched = Executors.newScheduledThreadPool(2);
sched.schedule(task, 5, TimeUnit.SECONDS);           // через 5 сек
sched.scheduleAtFixedRate(task, 0, 1, TimeUnit.SECONDS); // каждую секунду

// Отправка задач
pool.execute(runnable);            // submit без результата
Future<Integer> f = pool.submit(callable); // submit с результатом
f.get();                           // блокирует до готовности

// Завершение
pool.shutdown();                   // ждёт завершения текущих задач
pool.shutdownNow();                // прерывает потоки
pool.awaitTermination(5, TimeUnit.SECONDS); // ждём не дольше 5 сек
ThreadPoolExecutor — настройка под капотом детали
ThreadPool.java
// Настройка пула вручную
new ThreadPoolExecutor(
    2,                           // corePoolSize
    8,                           // maximumPoolSize
    60, TimeUnit.SECONDS,        // keepAliveTime для idle потоков
    new LinkedBlockingQueue<>(100), // очередь задач
    new ThreadFactory() { ... }, // как создавать потоки
    new ThreadPoolExecutor.CallerRunsPolicy() // политика отказа
);

7.5Future и CompletableFuture

CompletableFuture (Java 8) — асинхронные цепочки без блокировки. Аналог промисов в JS.

CFuture.java
// Асинхронное выполнение
CompletableFuture<String> cf = CompletableFuture
    .supplyAsync(() -> fetchFromDB())       // в ForkJoinPool.commonPool
    .thenApply(result -> result.toUpperCase()) // трансформация
    .thenApply(s -> "[" + s + "]")
    .exceptionally(e -> "ERROR: " + e.getMessage()); // обработка ошибки

String value = cf.get(); // блокирует

// Цепочки
CompletableFuture.supplyAsync(() -> getUserId())
    .thenCompose(id -> CompletableFuture.supplyAsync(() -> fetchUser(id))) // flatMap
    .thenAccept(user -> System.out.println(user));

// Комбинирование
CompletableFuture<String> a = CompletableFuture.supplyAsync(() -> "Hello");
CompletableFuture<String> b = CompletableFuture.supplyAsync(() -> "World");
CompletableFuture.allOf(a, b).thenRun(() -> System.out.println("Both done"));
CompletableFuture.anyOf(a, b).thenAccept(r -> System.out.println("First: " + r));

7.6java.util.concurrent коллекции

ConcurrentCollections.java
// ConcurrentHashMap — thread-safe HashMap, без глобального лока
// Блокирует только сегмент (bucket), высокая конкуррентность
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.putIfAbsent("key", 1);
map.computeIfAbsent("key", k -> expensiveCompute(k));

// CopyOnWriteArrayList — снимок при записи, быстрое чтение
// Для редких записей, частых чтений (event listeners)
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();

// BlockingQueue — producer-consumer
BlockingQueue<Task> queue = new LinkedBlockingQueue<>(100);
queue.put(task);    // блокирует если полна
queue.take();       // блокирует если пуста
queue.offer(task, 100, TimeUnit.MILLISECONDS); // с таймаутом

// Атомарные переменные
AtomicInteger   counter = new AtomicInteger(0);
AtomicLong      seqNum  = new AtomicLong(0);
AtomicBoolean   flag    = new AtomicBoolean(false);
AtomicReference<T> ref = new AtomicReference<>();

// CountDownLatch, CyclicBarrier
CountDownLatch latch = new CountDownLatch(3);
latch.countDown(); // каждый поток уменьшает счётчик
latch.await();     // ждёт пока не 0
