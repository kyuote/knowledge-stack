JVM и память

Heap, Stack, Metaspace, сборщики мусора, ClassLoader, JIT — понимание этих механизмов объясняет поведение Java в продакшене.

8.1Heap, Stack, Metaspace

memory.txt
JVM Memory
├── Heap                     // объекты + массивы, управляется GC
│   ├── Young Generation
│   │   ├── Eden             // новые объекты
│   │   ├── Survivor S0
│   │   └── Survivor S1
│   └── Old Generation       // долгоживущие объекты
├── Metaspace                // метаданные классов (вместо PermGen с Java 8)
│   └── Class metadata, method bytecode, static variables
├── Stack (per thread)       // фреймы вызовов, локальные переменные, ссылки
│   └── Frame per method call
├── PC Register (per thread) // счётчик команд
└── Native Method Stack      // для JNI

Объекты живут в Heap. Локальные переменные и ссылки — в Stack (каждый поток имеет свой). Сами объекты, на которые ссылаются, — в Heap. StackOverflowError — переполнение стека (глубокая рекурсия). OutOfMemoryError: Java heap space — переполнение кучи.

8.2Сборщики мусора

GC автоматически освобождает память недостижимых объектов. Minor GC — очистка Young Gen (быстро). Major/Full GC — очистка Old Gen (долго, stop-the-world паузы).

GCКогда использоватьПаузы
Serial GCоднопоточные приложения, маленький heapдлинные STW
Parallel GCпакетная обработка, throughput важнее latencyдлинные STW
G1 GCпо умолчанию Java 9+, большой heap (>4GB)предсказуемые, короткие
ZGCultra-low latency, heap до терабайт<1ms
Shenandoahlow latency, OpenJDK<10ms
Алгоритм работы G1 GC детали

G1 делит heap на регионы (~1-32MB). Отслеживает «мусорность» каждого региона. Во время Minor GC — копирует живые объекты из молодых регионов. Periodically — concurrent marking (параллельно с приложением). Mixed GC — собирает старые регионы с наибольшим количеством мусора (Garbage First).

Целевое время паузы задаётся через -XX:MaxGCPauseMillis=200 (по умолчанию 200мс).

8.3ClassLoader

ClassLoader загружает байткод классов в JVM. Работает по принципу делегирования родителю (Parent Delegation Model): сначала просит родителя загрузить класс, только если родитель не смог — загружает сам.

ClassLoader.java
// Иерархия ClassLoader
Bootstrap ClassLoader      // загружает rt.jar / java.base (нативный код C++)
└── Platform ClassLoader   // java.se.* (Java 9+, ранее Extension CL)
    └── Application ClassLoader // classpath приложения

// Получить classloader
ClassLoader cl = MyClass.class.getClassLoader();

// Кастомный ClassLoader — для горячей перезагрузки, изоляции
class HotReloadCL extends ClassLoader {
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] bytecode = readBytecodeFromDisk(name);
        return defineClass(name, bytecode, 0, bytecode.length);
    }
}

// Загрузка ресурсов
URL resource = MyClass.class.getResource("/config.properties");
InputStream is = MyClass.class.getResourceAsStream("/data.json");

8.4JIT-компиляция

JVM сначала интерпретирует байткод, затем «горячий» код (часто выполняемый) компилируется JIT-компилятором в нативный машинный код. Порог для компиляции — по умолчанию 10 000 вызовов метода.

JIT.java
// JIT делает оптимизации:
// - inlining: вставляет тело метода на месте вызова
// - escape analysis: объекты, не выходящие из метода, — на стек (не heap!)
// - loop unrolling: разворачивает короткие циклы
// - dead code elimination: убирает недостижимый код

// Из-за JVM warm-up:
// - приложение работает быстрее через 1-2 минуты после запуска
// - бенчмарки надо прогревать (используй JMH — Java Microbenchmark Harness)

// Принудительная компиляция (для отладки)
-XX:+PrintCompilation   // показывает что компилируется
-XX:CompileThreshold=100 // понизить порог для тестов

8.5Ссылки: WeakReference, SoftReference

Обычные ссылки — strong references: GC не соберёт объект пока есть strong ref. Слабые ссылки позволяют объекту быть собранным GC.

References.java
// WeakReference — собирается при следующем GC
// Использование: кэши, где ключ = объект (WeakHashMap)
WeakReference<byte[]> weakRef = new WeakReference<>(new byte[1024]);
byte[] data = weakRef.get(); // null если уже собрано GC
if (data != null) { /* используем */ }

// SoftReference — собирается только при нехватке памяти
// Использование: кэши изображений, результатов вычислений
SoftReference<BufferedImage> imageCache = new SoftReference<>(loadImage());
BufferedImage img = imageCache.get();
if (img == null) img = loadImage(); // перезагружаем если GC собрал

// PhantomReference — уведомление после финализации (очистка ресурсов)
// Сейчас вместо этого лучше Cleaner (Java 9+)

// WeakHashMap — ключи могут быть собраны GC
WeakHashMap<Key, Value> cache = new WeakHashMap<>();
// Когда key больше нигде не используется — запись удаляется автоматически
