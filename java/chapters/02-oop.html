ООП: классы и интерфейсы

Классы, наследование, абстракция, интерфейсы, sealed, record — основа Java-собеса. Нужно понимать не синтаксис, а когда что выбирать.

2.1Классы и объекты

Класс — шаблон. Объект — экземпляр класса в куче. Конструктор вызывается при new. Если конструктор не объявлен — компилятор добавляет no-arg конструктор автоматически.

Person.java
public class Person {
    // поля
    private final String name;  // final = нельзя переназначить
    private int age;

    // конструктор
    public Person(String name, int age) {
        this.name = name;       // this — ссылка на текущий объект
        this.age = age;
    }

    // getters / setters
    public String getName() { return name; }
    public int    getAge()  { return age; }
    public void   setAge(int age) { this.age = age; }

    // переопределяем Object.toString()
    @Override
    public String toString() {
        return "Person{name=" + name + ", age=" + age + "}";
    }

    // equals и hashCode — переопределяй вместе
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Person p)) return false;
        return age == p.age && name.equals(p.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}
Если переопределяешь equals — обязательно переопределяй hashCode. Иначе объекты не будут работать корректно в HashMap/HashSet.

2.2Наследование

Java поддерживает только одиночное наследование классов. extends — унаследовать класс. super — вызвать конструктор или метод родителя. Все классы неявно наследуют Object.

Animal.java
class Animal {
    protected String name;

    public Animal(String name) { this.name = name; }

    public String speak() { return "..."; }
}

class Dog extends Animal {
    private String breed;

    public Dog(String name, String breed) {
        super(name);    // вызов конструктора родителя — обязателен первым
        this.breed = breed;
    }

    @Override           // аннотация — защита от опечаток в сигнатуре
    public String speak() { return "Woof!"; }

    // super.speak() — вызов метода родителя
    public String both() { return super.speak() + " + " + speak(); }
}

// Полиморфизм: переменная типа Animal может хранить Dog
Animal a = new Dog("Rex", "Husky");
System.out.println(a.speak()); // "Woof!" — вызывается метод реального объекта

// Запрет наследования
final class Immutable { }  // final класс — нельзя унаследовать

2.3Абстрактные классы

Абстрактный класс нельзя инстанциировать напрямую. Может содержать как абстрактные методы (без реализации), так и обычные. Используй, когда есть общий код и общее состояние.

Shape.java
abstract class Shape {
    protected String color;

    public Shape(String color) { this.color = color; }

    // абстрактный метод — наследник ОБЯЗАН реализовать
    public abstract double area();

    // обычный метод — наследник может переопределить, но не обязан
    public String describe() {
        return color + " shape, area=" + area();
    }
}

class Circle extends Shape {
    private double radius;

    public Circle(String color, double radius) {
        super(color);
        this.radius = radius;
    }

    @Override
    public double area() { return Math.PI * radius * radius; }
}

2.4Интерфейсы и default-методы

Интерфейс — чистый контракт. Класс может реализовывать несколько интерфейсов. С Java 8 появились default-методы (с реализацией) и static-методы в интерфейсах.

Flyable.java
interface Flyable {
    // константа — неявно public static final
    int MAX_ALTITUDE = 10_000;

    // абстрактный метод — неявно public abstract
    void fly();

    // default-метод — реализация по умолчанию (Java 8+)
    default String describe() {
        return "I can fly up to " + MAX_ALTITUDE + "m";
    }

    // static-метод — вызывается через имя интерфейса
    static Flyable noOp() { return () -> {}; }
}

interface Swimmable {
    void swim();
}

// Класс реализует несколько интерфейсов
class Duck extends Animal implements Flyable, Swimmable {
    public Duck() { super("Duck"); }

    @Override public void fly()  { System.out.println("Flap flap"); }
    @Override public void swim() { System.out.println("Splash"); }
    // describe() — берётся из Flyable.default, можно переопределить
}

2.5sealed классы (Java 17)

Sealed класс ограничивает список разрешённых наследников. Даёт компилятору полную информацию об иерархии — удобно с pattern matching в switch.

Expr.java
// sealed — только перечисленные классы могут наследовать
sealed interface Expr permits Num, Add, Mul {}

record Num(int value)        implements Expr {}
record Add(Expr l, Expr r)   implements Expr {}
record Mul(Expr l, Expr r)   implements Expr {}

// Компилятор знает все варианты → exhaustive switch без default
int eval(Expr e) {
    return switch (e) {
        case Num(int v)      -> v;
        case Add(var l, var r) -> eval(l) + eval(r);
        case Mul(var l, var r) -> eval(l) * eval(r);
    };
}

2.6record (Java 16)

record — иммутабельный носитель данных. Компилятор автоматически генерирует: конструктор, геттеры, equals, hashCode, toString. Заменяет boilerplate-классы данных.

Point.java
// Декларация
record Point(int x, int y) {}

// Эквивалентно классу с:
// - final полями x и y
// - public Point(int x, int y) { this.x = x; this.y = y; }
// - геттерами x() и y()  (не getX!)
// - equals, hashCode, toString

Point p = new Point(3, 4);
System.out.println(p.x());      // 3
System.out.println(p);          // Point[x=3, y=4]

// Можно добавлять методы и валидацию в compact constructor
record Range(int min, int max) {
    Range {  // compact constructor — поля уже присвоены, только validate
        if (min > max) throw new IllegalArgumentException();
    }

    int length() { return max - min; }
}
Используй record для DTO, Value Object, ключей в Map. Нельзя наследовать record и нельзя сделать его mutable.
